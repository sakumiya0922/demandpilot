# DemandPilotを理解するための解説

このページは、面接で聞かれたときに「何を・なぜ・どう作ったか」を自分の言葉で説明するためのメモです。複雑な細部を覚える必要はありません。

## 1. 何を学ぶための開発か

**最優先:** PostgreSQLを使う、Docker Composeで環境を起動する、学習したモデルを別の処理から利用する。

**題材:** 需要予測。海外在庫適正化の業務経験があるため、モデルの意味を理解したうえでDBやアプリの技術習得に集中できると考えた。

MLflowは別PRで実装案を作成中です。動作確認が終わるまでは「習得済み」「完成済み」としません。

## 2. まず、この4つだけ説明できればよい

### PostgreSQL（保存）

Pythonで加工した取引データを、商品・取引・日次販売のテーブルに格納しています。Excelだけで処理するのではなく、DBから日次データを取り出して次の予測処理へ渡します。

- 確認するコード：[`src/demandpilot/db.py`](../src/demandpilot/db.py)
- 何を理解する？ テーブルとは何か、SQLでデータを保存・取得する意味

### Docker Compose（環境構築）

DB（PostgreSQL）とPythonの処理・画面（Streamlit）をコンテナで動かしています。環境を揃え、同じ手順で起動しやすくするためです。

- 確認するコード：[`compose.yaml`](../compose.yaml)
- 何を理解する？ コンテナとサービス、`db`と`app`を分ける理由

### モデル学習・推論（分離）

LightGBMを学習してモデルファイルに保存し、画面側ではその保存モデルを使った予測を表示します。学習と画面表示を毎回一緒に行いません。

- 確認するコード：[`src/demandpilot/modeling/train.py`](../src/demandpilot/modeling/train.py)
- 何を理解する？ 特徴量と目的変数、学習と推論の違い、時系列で学習／テストを分ける理由

### Streamlit（画面）

商品を選び、過去の販売、予測、精度、仮の補充数を画面で確認できます。補充数は現在庫・安全在庫の仮定値による簡易式です。

- 確認するコード：[`app/streamlit_app.py`](../app/streamlit_app.py)
- 何を理解する？ モデルが出した数値をユーザーの判断材料にする仕組み

## 3. よく聞かれる質問と説明例

**Q. なぜこの題材？**  
A. 需要予測自体は業務で経験していたため、未知だったDB・Docker・アプリ接続の学習に集中できたからです。

**Q. なぜLightGBMの精度が低いのに公開？**  
A. データの取込→DB保存→学習→評価→Web表示という工程を構築することが目的です。ベースラインとの比較で改善できなかったことも記録しました。

**Q. なぜクラウドに公開しない？**  
A. 今回はローカルで一連の構成を実装することを到達点としており、デプロイ・認証・運用は開発範囲外だからです。

## 4. 深掘りする順序

最初は上記4機能と実際に動く画面を理解してください。その後必要に応じて[詳細設計・再現情報](technical_reference.md)を確認すれば十分です。
